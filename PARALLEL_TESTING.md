# Parallel PostgreSQL test workflow

The normal suite uses one database named `gg_test`. Its session fixture drops and recreates that
database's tables, so two pytest processes using it can block or erase each other's schema.

Use `scripts/run_isolated_tests.py` whenever another agent or developer may already be testing:

```powershell
# Codex
.\.venv\Scripts\python.exe scripts\run_isolated_tests.py --label codex -- -q

# Claude, in another terminal at the same time
.\.venv\Scripts\python.exe scripts\run_isolated_tests.py --label claude -- -q
```

Arguments after `--` are passed to pytest. A focused run works the same way:

```powershell
.\.venv\Scripts\python.exe scripts\run_isolated_tests.py --label codex -- -q tests/test_security.py
```

## Isolation guarantees

Each invocation:

1. Validates that the base URL is local PostgreSQL and names a `gg_test...` database.
2. Connects to PostgreSQL's `postgres` maintenance database—not `gg_test`—using the local test
   connection settings.
3. Creates a random database such as `gg_iso_codex_18420_a1b2c3d4` from `template0`.
4. Gives pytest only that database through `TEST_DATABASE_URL`.
5. Uses `TEST_KV_BACKEND=database`, so rate-limit/cache state is isolated too; it never shares the
   local Redis database with another suite.
6. Uses unique pytest cache and temporary directories.
7. Builds a small allowlisted child-process environment. Production database, payment, mail,
   notification, preview and provider variables are not inherited.
8. Drops only the exact random database generated by that invocation, with a strict name check.

The runner refuses remote database hosts, `gg_site`, SQLite, and any database name outside its
`gg_iso_...` pattern. It never prints the database password. `--keep-database` is available for a
failed-run investigation; remove that generated database manually afterward.

The local Docker PostgreSQL role (`gg`) can create these databases. Start it first if needed:

```powershell
docker compose up -d db
```

This isolates database/schema, database-backed KV counters, pytest cache and temporary files. Tests
that deliberately use a fixed external port or a separately shared external service would still need
their own namespace; the current suite normally mocks those providers.
